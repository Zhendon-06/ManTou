# 生成应用闭环实施记录

## 任务复杂度与验收策略

新项目和续跑草稿按项目计划中的界面、核心验收、状态变更和脚本数，以及本轮检索到的相关 Android 能力，自动选择编排重点和执行上限。已发布项目的后续修改以常规范围为起点，结合本轮相关系统能力调整。

模型调用次数是保护上限。按依赖逐文件生成和后续修复共享总预算，传输重试保有自己的上限。交付以构建、运行检查和验收结果为准。

设置 → 验收策略，控制设备覆盖和页面自测要求。默认覆盖手机及项目声明的尺寸，页面自测未通过可以记录警告。严格验收增加平板尺寸，并要求页面自测通过。各策略保留核心功能验收、质量门禁和截图证据。

## 后续工作及验收条件

1. 宿主生命周期回归：计数器、待办、表单样例执行真实旋转、前后台和 Activity 重建；验证可见、可操作和状态恢复。现有临时挂载回归不替代这些测试。
2. 测试数据隔离：每次运行独立存储，用例显式重置；验证测试不影响用户数据，以及销毁重建后数据仍可恢复。
3. 多状态视觉证据：视觉状态声明 setup/actions/waitFor/assertions，采集操作后的截图，证据关联用例及代码哈希。
4. 修复收敛：保存候选快照和诊断指纹，区分环境、宿主、生成代码故障；连续无进展时重新诊断，出现核心回归时恢复较好候选。
5. 恢复与交付：持久化任务检查点，校验哈希后复用检查结果，提供版本回退、验收报告和问题回流。

后续能力按各项验收条件单独验证。

## 验证

单元测试覆盖任务复杂度推断、验收策略迁移、基础门禁和逐文件生成的总预算。
